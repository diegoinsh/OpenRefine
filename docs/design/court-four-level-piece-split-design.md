# 法院诉讼卷宗「按四级件题名分件」设计

- 状态：**方案已定，待实施**
- 日期：2026-11-06
- 关联：`ruyi-capability-platform/docs/TODO-未实现功能登记清单.md` UNIMPL-004
- 关联：`docs/design/court-catalog-four-level-layering-design.md`（四级叠加，只管分类，不管分件）
- 涉及仓库：`ruyi-aimp`（分件）、`ruyi-capability-platform`（目录模板与接口）、`OpenRefine`（编排）

## 一、结论摘要

1. **客户的诉求是分件粒度变化，不是命名变化**：现行分件会把同一二级目录下的多份不同文种合并成一个件（如「原告举证材料」6 页里含证据目录、转账回单汇总表、现金交付说明、催收短信记录），客户要求按编目规则 CSV 的**第 4 级（每行一个文种 × 责任者）** 拆开。
2. **分件金标准**：`(文种, 责任者)` 二元组是否变化。文种变或责任者变即切；两者都不变才合并。
3. **推翻「自顶向下清单对齐」路线**：切分依据是页级可判定的 `(文种, 责任者)` 信号，不是"拿一份清单去卷内找页"。CSV 的职责是**命名与渲染模板**，不是定边界。
4. **采纳「级联细分」路线**：主分件先定二级（粗），再在件内按 `(文种, 责任者)` 细化（细）。`ruyi-aimp` 已有 `split_party_identity_pieces` 实现了同一套判定，只是被 `_is_identity_title` 门禁限制在身份/委托材料，**泛化门禁即为主体工作**。
5. **UNIMPL-004 采纳但必须改主键**：`(caseType, level3)` → `(caseType, level1, level3, party)`。

## 二、术语修正：四级是什么

| 级别 | 含义 | 载体 |
|---|---|---|
| 一级 | 正卷 / 副卷 | 目录模板 |
| 二级 | 二级目录分组（如「原告举证材料」） | 目录模板 |
| 三级 | 件题名（标准文种名，如「借条」） | 目录模板 `level3` |
| 四级 | 三级件名的定制渲染结果（如「原告赵建明借条」） | 目录模板 `level4Template` |

**关键**：四级不是比三级更细的"目录层级"，而是同一文种的**定制命名**。分件粒度对应的是 CSV 的**行**（文种 × 责任者），不是"第四层目录节点"。

## 三、分件金标准

```
切分条件 = 文种变化 OR 责任者变化
合并条件 = 文种相同 且 责任者相同
```

| 场景 | 判定 |
|---|---|
| 借条 → 欠条（文种变） | 切 |
| 原告张三借条 → 被告李四借条（责任者变） | 切 |
| 原告张三借条 → 原告张三借条（都不变） | 合（同文种多份合一） |
| 律师事务所公函 → 所附律师执业证（规则特例） | 合（CSV 明确「公函及执业证」为一件） |

CSV 的「当事人归属」列即责任者维度；空值表示责任者为法院等中立主体。

## 四、数据事实（编目规则 CSV）

统计口径：`法院民事一审案件编目规则-导入模板-修订.csv`，六列
`一级目录,二级目录,排序号,原题名,新题名模板,当事人归属`。

| 指标 | 正卷 | 副卷 | 合计 |
|---|---|---|---|
| 行数（= 四级件类型数） | 436 | 121 | **557** |
| 二级分组数 | 32 | 24 | 56 |
| 文种数（按原题名去重） | 392 | 121 | 513 |
| `(文种, 责任者)` 唯一数 | 436 | 121 | **557** |

- **`(文种, 责任者)` 跨二级重复数 = 0**：`(文种, 责任者)` 是天然唯一键，可直接做主键。
- 23 个文种发生角色分叉（身份证 / 户口本 / 户籍信息 / 常住人口信息 / 流动人口信息等，各分原告、被告、第三人三行）——这正是"件名出来后按角色一分为二"的数据基础。
- 当事人归属分布：空 391、原告 98、被告 31、第三人 22、其他诉讼参与人 15。约 70% 的四级件责任者为法院（空值）。
- **56 是"材料类型全集"的二级分组数，不是单卷件数**。单卷只会出现其中一部分，不能拿它当分母。

## 五、实测（真实卷 2158，51 页）

方法：取逐页 OCR 文本人工核验，按金标准判定可拆点。**样本 n=1，非算法跑批；拆准率未测。**

| 现行件 | 页 | 实际内容 | 四级拆分数 |
|---|---|---|---|
| 04 应诉通知书（附送达回证） | 7–8 | 应诉通知书 + 送达回证 | 2 |
| 06 答辩状及附件 | 11–12 | 答辩状 + 借款本息核减计算表 | 2 |
| 07 原告身份证明 | 13–14 | 冯桂兰身份证 + 宋文斌身份证（**同文种、责任者不同**） | 2 |
| 08 被告主体资格材料 | 15–16 | 营业执照 + 法定代表人身份证明书 | 2 |
| 09 授权委托书（原告） | 17–18 | 两名原告各一份 | 2 |
| 11 原告举证材料 | 21–26 | 证据目录 / 转账回单汇总表 / 现金交付说明 / 催收短信记录 / 2 页复印件 | **4–6** |
| 12 被告举证材料 | 27–28 | 证据目录 + 待定 | 1–2 |
| 19 送达回证及 EMS | 39–40 | 送达回证 + EMS 邮寄查询单 | 2 |
| 其余 17 件 | — | 单一文种 | 各 1 |

**汇总：25 个有效件 → 约 34–38 件，整体倍数约 1.4–1.5 倍；局部（举证材料类）可达 4–6 倍。**

这修正了早期"整体 4–7 倍"的推断：**倍数是局部的，不是全局的**。全卷看约 1.5 倍，痛点集中在举证材料、身份证明、送达类这几个二级。

**LLM 调用量**：现状是"每件首页 1 次"（有效件 25 次）。采用轻量三级判定后，只有"被判为材料首页
且 title 为空"的页才补抽一次，调用量约 25 → 35 次，**增量约 1.4 倍**（按页全抽的上界是 1.9 倍，
不必达到）。判定信号全部复用现有产出，见 §6.4。

**实测暴露的难点**：证据类材料多为复印件，OCR 质量差（件 11 的 P22/P23 文本为 `×`、竖排碎片），标题不可识别。**这类页无法靠文本判文种，必须依赖版面模型（l0.pt 标题块）+ 视觉特征**，是拆准率的主要风险点。

## 六、架构判定

### 6.1 推翻：清单驱动 / 自顶向下对齐

理由：
- 缺输入。CSV 是全集模板，不是单卷应含件清单；客户并未提供逐卷目录。
- 方向错。分件边界由 `(文种, 责任者)` 这一页级信号决定，不需要"按清单找页"。
- 退化后无收益。若拿全集当靶子，本质仍是在件内做细分，只是把两段合成一次推理，风险却高一个数量级。

### 6.2 采纳：级联细分（coarse-to-fine）

```
页级 OCR + 版面（l0.pt 标题块）+ 页级责任人
        ↓
主分件：确定二级/件边界（现状，保留）
        ↓
件内细分：按 (文种, 责任者) 变化再切（新增）
        ↓
四级题名渲染（level4Template）+ 一二级目录映射
```

复用现状（无需重做）：
- `l0.pt` 版面模型：标题块坐标，与分件粒度无关，**不改**。
- `extraction_quality` 的 L0 规则 / L1 融合打分：抽取质量校准，与分件正交，**不改**。
- `PageSplitModel`（LR，页级 `P(本页=新文书首页)`）：任务形态不变，只需按新粒度重新标注与调阈值，**重训不重构**。
- `split_party_identity_pieces` / `_resplit_identity_section` / `_party_side`：判定依据与金标准同源，**泛化门禁即可**。

### 6.3 真正的增量

| 工作项 | 说明 |
|---|---|
| 泛化门禁 | `_is_identity_title` → 按二级分组选候选文种集，覆盖全部二级 |
| 件内逐页文种识别 | 从"件首页出题名"扩到"每页判文种"，是主要成本与准确率瓶颈 |
| 复印件/低质页兜底 | 靠 l0.pt 标题块 + 版式特征，不能只靠 OCR 文本 |
| 四级题名渲染 | 消费目录模板的 `level4Template`，补 `party` 变量 |
| LR 阈值校准 | 复用现有模型，先只重定阈值；召回不足时再补件内边界标注做增量训练 |

### 6.4 轻量判定：复用现有信号，不重训模型

件内细分**不新增重型 LLM 调用**，判定信号全部来自现有产出，按成本从低到高三级：

| 层 | 信号 | 来源 | 成本 |
|---|---|---|---|
| L1 规则 | 页首形态（`detect_title_like`）、落款 / 日期 / 文号 / 印章 | 现有逐页结果 + l0.pt | 0 |
| L2 词表 | 页首 N 行匹配四级文种词表（557 条） | 编目模板导出 | 0 |
| L3 模型 | `PageSplitModel`（LR）的 `P(本页=新文书首页)`，重定阈值 | 现有 `lr_model.joblib` | 0（推理已在跑） |

信号可得性（已核实）：

- 卷级分件时 `splitVolumePieces(pageTitles, pageParties, partyRoles, ...)` 已把**逐页 title 与 party 全量传入**（`AimpLlmClient.java:550-563`），件内细分可直接消费。
- `l0.pt` 每页都跑，`title_regions` 本就产出（`seal_removal.py:207-311`）。
- LR 每页都已推理过（用于决定是否跳抽），只是 P 值用完即弃，**留存即可复用**。

需要的小改动（均不涉模型训练）：

1. 逐页抽取时**留存 LR 的 P 值**（现在只用完即弃）。
2. 主分件完成后，在每个件的页区间内跑一次 L1→L2→L3 判定。
3. 只对「被判为材料首页且页级 title 为空」的页补一次 LLM 抽取（用于命名），其余页不调模型。

**边界**：LR 的训练标签是**件级边界**（`gt_piece_no` 切换点），对「件内材料边界」的召回尚未验证。
因此先按"不重训、只重定阈值"上线，并用 mock 新卷量化召回；若不足，再补少量件内边界标注做
**增量训练**，不从零重训。

## 七、与 UNIMPL-004 的关系

UNIMPL-004 是**目录分类架构**（模板为基、反馈为覆盖、编译期索引），本次是**分件架构**。两者正交但互补：UNIMPL-004 提供靶子集（四级文种 + 渲染模板 + 排序），四级分件消费它。

### 7.1 采纳的部分

1. 一套目录模板（`rcp_template` type=catalog，payload 含 level1/level2/entries）。
2. 反馈只写覆盖层（`catalog_override`），`catalog_calibration` 仅审计。
3. 启动/版本变更时编译为有序索引，读路径只做一次精确查找 + 一次别名查找。
4. `caseType` 纳入作用域，民/刑/行同名件不互相覆盖。
5. 一至四级同源：`getExtractionResult(withCatalog=true)` 与 `getCatalogClasses` 共用同一索引。

### 7.2 必须修正的部分

**主键 `(caseType, level3)` → `(caseType, level1, level3, party)`。**

依据：
- 数据上 `(文种, 责任者)` 跨二级重复为 0，是唯一键。
- 身份证在原告/被告/第三人下是三行不同定义；若只用 `level3` 做键，「身份证」只有一条 entry，`level4Template` 只能渲染一个角色，被告身份证必然渲染错。
- "件名出来后按角色一分为二"正是依赖该维度。

`entries[]` 建议结构：

```json
{
  "level3": "身份证",
  "party": "原告",
  "aliases": ["居民身份证"],
  "matchType": "exact",
  "level4Template": "原告{原告}身份证",
  "order": 11
}
```

唯一键：`(caseType, level1, level3, party)`。

|---|---|---|
| P0 | 目录模板补 `party` 维度；四级文种 + 渲染模板可导出为 aimp 消费的靶子集文件 | 557 条四级件可完整导出，`(文种,责任者)` 无冲突 |
| P1 | aimp 泛化 `_is_identity_title` 门禁，按二级分组取候选文种集做件内细分 | 2158 卷件数 25 → 34–38，件 11 拆出 ≥4 件 |
| P2 | 件内逐页文种识别 + 复印件兜底；LR 重训 | 拆准率与召回达基线（基线值待 P1 实测后定） |
| P3 | 四级题名渲染接入接口；`level4Title` 从校准入参转为正式响应字段 | 下游可仅凭响应拿到四级件名与一二级目录 |
| P4 | 灰度与回退开关：四级分件可按项目/模板开关，关闭时行为与现状逐字节一致 | 开关关闭不影响既有验收数据 |

## 九、风险与待定

1. **低质复印件**：证据类材料 OCR 差，文种只能靠版面 + 视觉。是拆准率最大风险，需在 P2 单独度量。
2. **文种误判会放大件数**：件数从 25 涨到 38 时，每个误判都变成额外的错误件，评估指标需从"件级 F1"补"件数偏差"。
3. **同文种多份的合并边界**：责任者相同即合并，但若卷内同一责任者有多份不同内容的借条（如换据），按规则合并为一件——需与客户确认这是否符合其归档习惯。
4. **待定**：`level4Title` 是否作为正式响应字段对下游开放（当前仅在校准入参中出现）。
5. **待定**：灰度周期与验收样本范围（建议至少 3 卷真实卷宗，覆盖有/无举证材料两类）。

## 十、验收标准

- 同一 `level3` 在民事/刑事下可分别配置，互不覆盖。
- 件内细分前后，一级/二级目录归属不变（分件只改粒度，不改分类正确性）。
- 2158 卷：件 07 拆为两份身份证、件 11 拆出 ≥4 件、整体件数落在 34–38。
- 四级分件开关关闭时，输出与改造前一致。
- 下游仅凭 `getCatalogClasses` / `getExtractionResult` 响应即可还原四级的件名、一二级目录与排序。
