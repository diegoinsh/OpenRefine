## 1. 档案门类划分

### 1.1 划分依据

《机关档案管理规定》（国家档案局令第 13 号）第二十三条明确了机关档案的门类划分。据此，机关档案常见门类包括：文书档案、科技档案、人事档案、会计档案、专业档案，以及照片、录音、录像、实物等特殊载体档案，另有业务数据、公务电子邮件、网页信息、社交媒体等新型档案。

本平台界面「文档类别」下拉所列 17 个门类即按上述规定整理，与 AIMP 侧 `_ARCHIVE_CATEGORY_RULES` 一一对应（未匹配门类回退「文书档案」）。

## 2. 法院随案生成的案卷卷宗：门类归属

**结论：属于专业档案，具体种类为「人民法院诉讼档案」（第一批政务类序号 16，专业主管部门为最高人民法院）。**

关键区分：

| 档案对象 | 门类归属 | 说明 |
|---|---|---|
| 随案审判活动形成的卷宗（起诉状、笔录、裁判文书、送达回证等） | **专业档案 → 人民法院诉讼档案** | 《人民法院诉讼档案管理办法》第二条：诉讼档案是**国家重要的专门档案之一** |
| 法院自身的行政公文（通知、请示、报告、函） | 文书档案 | 属机关履行一般管理职能形成的文件 |

管理依据：

- 《人民法院诉讼档案管理办法》（法〔2013〕283 号，2014-01-01 施行）——归档时限（结案后 3 个月内移交，特殊情况不超过 6 个月）、分类编号、检索工具编制、利用范围等。
- 《人民法院诉讼文书材料立卷归档办法》（〔84〕法办字第 5 号）——材料排列顺序、立卷要求。
- 《人民法院执行文书立卷归档办法（试行）》（法发〔2006〕11 号附件）——执行案件卷内目录与卷内备考表要求。
- 《关于人民法院案件案号的若干规定》（法〔2015〕137 号）——案号构成规则。

两者常被混用的实务区别：卷宗封面通常**并立正卷与副卷**（涉密、合议庭评议等材料入副卷），副卷不对外提供利用；未使用信息系统管理档案的法院，须编制「案号、案由和当事人名称索引」，即三个必备检索入口。

## 3. 著录字段标准

### 3.1 行业通用标准：DA/T 18—2022《档案著录规则》

2022 版将著录项目由 1999 版的 7 大项改为**7 大项、35 小项**：标识、背景、内容与结构、查阅与利用控制、相关档案材料、附注、著录控制。

文件级核心组成及其约束性：

| 著录项目 | 约束性 | 对应本平台提取要素 |
|---|---|---|
| 题名 | 必著 | 题名 |
| 责任者 | 必著 | 责任者 |
| 日期 | 必著 | 成文日期 |
| 档号 | 必著 | （由系统生成，不提取） |
| 文件编号 | 有则必著 | 文号 |
| 密级 | 有则必著 | 密级 |
| 公开属性 | 有则必著 | — |
| 开放标识 | 必著 | 开放状态 |
| 保管期限 | 必著 | 保管期限 |
| 范围和提要 / 人名 / 稿本 / 文种 / 附件 / 载体形态 / 生成方式 / 整理情况 等 | 选著 | 未涉及 |

要点：**密级与开放标识在标准中并非「可选」，密级为「有则必著」、开放标识为「必著」**；保管期限同样是必著项。这与档案实务中「涉密文件必标密级、归档文件必标开放状态」的要求一致。

### 3.2 人民法院诉讼档案的著录层级与字段

诉讼档案实行**案卷级 + 卷内文件级**两级著录（《人民法院诉讼档案管理办法》第八条、第二十条）。

**两级著录的最直接依据**：《人民法院电子诉讼档案管理暂行办法》（法〔2013〕283 号印发）的"案卷级著录"一节逐项列明案卷级元数据，共 6 大项（原文）：

| 大项 | 项目 |
|---|---|
| 1. 案卷与责任者 | 案号、案由、当事人、审判程序、审理结果、审判法院、合议庭成员、承办人、书记员、鉴定者、归档者、接收者、著录者、迁移者 |
| 2. 载体形态 | 总册数、正卷册数、副卷册数、证物袋数量、光盘数量、光盘编号 |
| 3. 密级与保管期限 | 密级、保管期限 |
| 4. 时间 | 立案日期、结案日期、归档日期、迁移日期、销毁日期 |
| 5. 电子文件挂接 | 卷内文件（序号、标题、电子文件路径） |
| 6. 排检与编号 | 档号、相关案号、参见号、全宗名称、版权 |

《人民法院诉讼档案管理办法》另定检索点与编号规则：

- **第八条**："使用信息系统管理档案的人民法院，应当编制**案卷级和卷内文件级目录索引**；未使用信息系统管理档案的人民法院，应当编制**案号、案由和当事人名称索引**。"（案号、案由、当事人为法定检索入口）
- **第九条**：封面加盖"归档"章，区分案件类别，按"**年度、一案（册）一号**"编号、排架。
- **第二十一条**：保管期限分**永久**和**定期**两种，**定期分为 60 年和 20 年**。
- **第二十四条**：保管期限从裁判文书发生法律效力的下一年起算；同一案件因不同审级、不同年代形成的案卷，从终审结案的下一年起算。

**① 案卷级（卷宗封面，一卷一号）**

| 字段 | 取值说明 |
|---|---|
| 案号 | `（收案年度）+ 法院代字 + 类型代字 + 案件编号 + 号`，如「（2023）京0105民初1234号」 |
| 案件类别 | 刑事 / 民事 / 行政 / 执行 / 国家赔偿 / 审判监督 |
| 案由 | 当事人争议的法律关系性质，如「民间借贷纠纷」「买卖合同纠纷」 |
| 当事人 | 原告、被告、上诉人、申请人、被执行人（正卷可查） |
| 收案日期 / 结案日期 | 卷宗封面「收案日期」「结案日期」栏；结案日期填写宣判日期（1991 办法第二十五条） |
| 审判组织 / 承办人 | 独任或合议庭成员 |
| 裁决机关 | 作出裁判的法院（二审案件含原审法院） |
| 结案方式 | 判决 / 裁定 / 调解 / 撤诉 / 终结（执行案件另有法定清单，见 3.4） |
| 保管期限 | **永久 / 60 年 / 20 年**（法〔2013〕283 号第二十一条；非上述取值时按原文著录，见 3.4） |
| 卷号、册号、正卷/副卷标识、归档日期 | 归档编号信息 |

**② 卷内文件级（卷内目录，一件一号）**

项目名称与填写规则的依据：

- 《人民法院诉讼文书材料立卷规范》（法〔2013〕283 号附件 1）**第二十条**："卷内目录应当按照文书材料排列顺序**逐件逐项**填写。卷内目录**除最后一件需填写起止页号外，其余只填起始页号**。"
- 《人民法院诉讼文书立卷归档办法》（法〔办〕发〔1991〕46 号）**第二十四条**："卷内目录应按诉讼文书材料排列顺序逐件填写。**一份诉讼文书材料编一个顺序号**。"（即"件"的界定口径）
- 同办法**第二十三条**："页号一律用阿拉伯数字编写在有文字正面的右上角，背面的左上角。**卷宗封面、卷内目录、备考表、证物袋、卷底不编号**。"
- 同办法**第二十五条**："卷宗封面、卷内目录要用毛笔或钢笔按规定项目逐项填写齐全，字迹要工整、规范、清晰。**结案日期填写宣判日期**。"
- 项目名称实务沿用 **GB/T 9705—2008《文书档案案卷格式》4.3**：**顺序号、文号、责任者、题名、日期、页号、备注**。

| 字段 | 取值说明 |
|---|---|
| 件号（顺序号） | 按材料排列顺序逐件编号 |
| 责任者 | 制作该文书的法院、审判庭，或当事人提交文书的署名人 |
| 文件题名 | 如「×××诉×××民间借贷纠纷一案民事判决书」 |
| 文件编号 | **诉讼档案语境下即案号**（非发文字号） |
| 成文日期 | 裁判文书落款日期或文书形成日期 |
| 页号 | 逐页编号，卷内目录填起始页号，最后一件填起止页号 |
| 备注 | 其他说明 |

### 3.3 密级、开放标识与保管期限的取值口径

- **密级**：依 **GB/T 7156《文献保密等级代码》**，取值 **公开 / 内部 / 秘密 / 机密 / 绝密**；标注在版心左上角或标题下方呈独立字样。**页面无密级字样时本要素留空**，不得给出默认值。
- **开放标识**：取值 **开放 / 控制 / 延期开放**；通常出现在「信息公开选项」「开放标识」处，例如「信息公开选项：主动公开」应著录为「开放」。诉讼档案正卷扫描件通常不标此项，无字样时留空。
- **保管期限**：标准值为 **永久 / 60 年 / 20 年**（法〔2013〕283 号第二十一条）。**能对应到标准值的等效表述按标准值归一**（如「定期 60 年」「六十年」→「60 年」，「永久保管」→「永久」）；**对应不上的非等效取值按原文著录、尊重原文**（如「30 年」「10 年」原样保留）；页面无字样时留空。

密级与开放标识容易被误读为「只有涉密单位才填」，但在 DA/T 18—2022 中二者分别是「有则必著」与「必著」，归档质检中属于必查项。

### 3.4 卷内 / 卷级字段分表与卷级汇总口径（本项目实现口径）

**决定一：卷内表只放卷内目录法定项目与件级信息，整卷同值的卷级要素一律落卷级表。**

依据：法〔2013〕283 号把 案由 / 当事人 / 审判程序（审级）/ 审理结果（结案方式）/ 密级 / 保管期限 列入**案卷级元数据**（见 3.2 的 6 大项）；它们整卷同值，逐件重复写入卷内行属系统冗余展示，不是著录位置。

| 表 | 列（按实际顺序） |
|---|---|
| **卷内**（一件一行） | 案卷号、件号、起止页号、页数、题名、责任者、文号、成文日期、文件名、提取状态、备注、**文件夹路径** |
| **卷级**（一卷一行） | 案卷号、题名、责任者、起始时间、终止时间、总页数、卷内文件份数、**案由、当事人、审级、结案方式、密级、保管期限、开放状态**、**文件夹路径** |

- 两张表的「文件夹路径」都固定排在**最后一列**（长路径不占版面）；
- 卷内表不再生成卷级要素列，卷内行也不再建立这些要素的页定位映射。

**决定二：卷级要素不做独立提取，一律由卷内件级取值汇总得出。**

依据：《人民法院诉讼档案管理办法》第八条要求编制**案卷级和卷内文件级目录索引**——卷级行是卷内各件的汇总，不另做一次"卷级提取"。封面页（卷前页）作为普通一页参与提取，其取值经 `previous_extractions` 上下文回填给各件，因此不会漏。

**策略分层：件级规范化 vs 卷级聚合**（避免同一规则在两处各写一遍）

| 层 | 职责 | 典型规则 |
|---|---|---|
| 页级（AIMP） | 单页取值的过滤与归一 | 文号须落在标题下方独立成行、题名须落在页面顶部、结案方式白名单、保管期限等效值归一、无字样留空 |
| **件级（Java）** | **要素值自身的规范化**，产出「件级最终值」 | 当事人：剥离「原告/被告/上诉人…」等诉讼地位称谓、空白与标点都作分隔符、件内去重、统一为全角逗号连接；证件类件不取成文日期、无署名材料（证物处理单等）不取责任者 |
| **卷级（Java）** | **跨件聚合**，输入只读件级最终值 | 当事人并集＋低频去噪＋**错别字按「同件共现＋件数众数」归并**、结案方式取成文日期最晚、密级/开放状态取最严档、案由/审级/保管期限取众数 |

卷级汇总的输入**就是件级最终值**（与卷内行同源、同一份 `rowValues`），不另取一份原始页级抽取结果；件级已做的规范化**不在卷级重写**。反之，"跨件一致性"类判断（低频去噪、众数、取最晚、取最严）件级看不到其他件，只能在卷级实现，不属于重复。

| 卷级要素 | 汇总规则 |
|---|---|
| 当事人 | 件级已把每件的当事人值规范化为「全角逗号连接的单个人名」；卷级只做**并集**：按「，」拆 → 去重保序 → **低频去噪** → **错别字按「同件共现＋件数众数」归并**（见下）→ 以全角「，」连接 |
| 结案方式 | 取**最终结论**：按各件成文日期排序，取最晚一件的取值。过程性记载（如调解笔录页抽到的「调解」）会被其后判决书的「判决」覆盖 |
| 密级 | 取**最高档**（整卷从严）：绝密 5 ＞ 机密 4 ＞ 秘密 3 ＞ 内部 2 ＞ 公开 / 非密 / 不涉密 / 普通 1 |
| 开放状态 | 取**最严一档**：控制 / 不开放 / 限制使用 3 ＞ 延期开放 2 ＞ 开放 / 主动公开 1 |
| 案由、审级、保管期限 | 取**众数**（出现件数最多的取值）；平票取先出现的 |
| 整卷无任何件级取值 | 留空，不臆造默认值（如密级页面无字样时为空） |

**当事人低频去噪的口径（相对判据，不是固定阈值）**：以「件间一致性」做交叉验证——

- 卷内**存在**重复出现的当事人 ⇒ 说明有可对照的一致性信号，只出现在一个件上的取值没有旁证，多为该页误读（错字、乱抽的「原告 / 被告」等），**剔除**；
- 卷内**所有**取值都只出现一次 ⇒ 本卷没有可对照的信号，「只出现一次」不再是噪声特征（小卷、当事人本就单一），**全部计入**，避免把真实当事人删光。

**同类字段为何不套用此规则**：密级 / 开放状态一旦出现即有效（一次「内部」也要整卷从严），按频次过滤会丢真值；结案方式在二审调解结案的卷里「调解」可能只出现一次却是最终结论，故取「成文日期最晚」而非频次最高；案由 / 审级 / 保管期限的众数本身已是一致性判据，平票时取先出现的（等于用卷内顺序兜底，与上条兜底同向）。

**当事人错别字的归并口径（同件共现 ＋ 件数众数）**：低频去噪防的是「单件偶发噪声」，防不了**重复出现在多个件上的系统性错字**——错字多来自手写件（答辩状、上诉状的署名、送达回证的签收等），实测 JZ07-2024-M2-0241 把「袁凤莲」写成「袁风莲」，「袁风莲」在 ≥2 个件里重复出现并与正字并存，低频去噪便覆盖不到，卷级当事人凭空多出一人。

**为什么不能只看编辑距离**：兄弟姐妹的名字常只差一个字（「袁凤仙」「袁凤鸣」互为**编辑距离 1**），与错字「袁风莲」对正字「袁凤莲」的距离完全一样，**单凭字面无法判断谁是错字**。

**为什么也不能只看「来源可信度」**：曾试以「法院打印件／证件类」件名做可信名单，但实测**送达回证的受送达人是手写签收**，其抽出的恰恰是错字「袁风莲」——错字被自己的来源「认证」为正确，判据反被污染。故不采用来源白名单。

**实际判据（三条件齐备才归并）**：

1. **等长且编辑距离为 1** —— 只认「一字之差」（替换），不比插入/删除，避免把名字长短不同的人并掉；
2. **从未同件共现** —— 兄弟姐妹会在**同一件里并列出现**（判决书首部把当事人同列），而错字与正字**互斥**，同一件不会两者都有；
3. **件数众数** —— 错字是少数派，正字在卷内出现的**件数更多**，故归并到「件数最多的近邻」。

任一条件不满足即**保持原样**（件数相同裁决不了、曾同件共现则是两个不同的人）。例：「袁风莲」与「袁凤莲」等长、差一字、从不同件、件数更少 → 归并；「袁凤仙」与「袁凤鸣」虽同样差一字，但**同件并列出现** → 绝不动。

卷级题名（「立卷法院」+「关于」+「当事人」+「案由」+「一案」+「的审级」+「诉讼档案」）中的当事人、案由、审级同样取上述汇总结果，避免被单页噪声（如庭审笔录页抽出的「原告，被告」）带偏；**当事人超过 3 人时，列前 3 位、第 4 位起以「等」概称**（如「郭长海，郭秀萍，郭秀梅等」），依 GB/T 9705—2008 3.1.3.3「文字应力求简练、明确」。

**结案方式**：目前无公开的全国统一代码表（《人民法院案件信息业务标准》按案件类型分列、未公开全文），实务口径为 判决 / 调解 / 裁定 / 撤诉 / 移送 / 终结；**执行案件有法定清单**——法发〔2014〕26 号第十四条：执行完毕、终结本次执行程序、终结执行、销案、不予执行、驳回申请。

**决定三：卷级「责任者」只著录主要责任者（本卷立卷法院），件级责任者维持逐一著录。**

依据 **DA/T 18—2022 8.1.1.2**：「文件级著录单元责任者有多个时，应逐一著录；**案卷级以上（含案卷级）著录单元责任者有多个时著录主要责任者**，立档单位本身是责任者的必须著录。」

- **件级**（卷内表「责任者」）：公文制发机关与当事人提交材料（起诉状、答辩状、上诉状、授权委托书等）的署名者**逐一著录**——当事人材料的主体就是该件的责任者，必须提取。实测 0241 各件已按此产出（如「袁连顺，袁凤莲」），口径正确，维持不变。
- **卷级**（卷级表「责任者」）：只著录**主要责任者 = 本卷立卷法院**（卷内制作文书件数最多的法院，避免取到原审法院）；识别不出立卷法院时才退回卷内责任者全集，避免整列留空。
- 多个责任者之间统一用**全角逗号**（与件级取值同一分隔符），不再出现半角「,」。

**决定四：卷级「卷内文件份数」按卷内件数计，不按扫描文件个数计。**

依据 **GB/T 9705—2008 3.1.3.6**「装订的案卷要填写总页数，不装订的案卷要填写本卷的总件数」与 **DA/T 8—2022 8.1.6.4**（案卷级著录「案卷内文件数量」）；浙江省《综合档案馆电子目录数据库结构与交换格式》亦把「卷内文件份数（WJFS）」列为案卷级著录项。

- 「卷内文件份数」= **卷内件级条目数**（一卷 21 件即 21）；「总页数」= 各件页数之和。
- 此前取 `unit.pages.size()`（目录下扫描文件个数），会把卷宗封面、卷内目录、备考表、卷底、证物袋一并计入，口径偏大（实测 0241：扫描文件 64 / 件数 21 / 件内页数 58，三个数互不相等）。

**决定五：证件类件不著录成文日期；卷级「起始时间／终止时间」可点回取值页。**

- **证件类件（居民身份证、常住人口登记表、户口簿、营业执照、企业信用信息公示报告、法定代表人身份证明）不取成文日期**：证件不是诉讼文书，证面上的**签发日期／有效期不是「文书形成日期」**，抽出来会把整卷「起始时间」拉到证件签发那年（实测身份证日期污染卷级起始时间）。页级识别到证件名时，题名置为证件名的同时**清空成文日期与文号**，该件在「卷内」表成文日期留空。
- **卷级「起始时间／终止时间」点击定位到取到该日期的那一页**：二者分别取各件成文日期的最早／最晚值，来源页按该日期取值匹配记录；此前这两列与普通非要素列一样只跳本卷首件首页，指向不对。

**决定六：无署名材料（证物处理单等表格）的责任者留空。**

依据：DA/T 18—2022 的责任者是「对档案内容进行创造或负有责任的」组织或个人，须以**署名、落款或印章**为据。证物处理单、卷内目录、备考表这类纯记录／交接表格自身没有署名栏，本就没有责任者；模型却容易把表格正文里提到的当事人／机关名当成责任者（实测 SZ05 的「证物处理单」被抽出正文中的「被告苏州恒盛精密机械有限公司」）。故：

- 页级提示词明确：纯记录／交接类表格（证物处理单、卷内目录、备考表等）自身没有署名栏，责任者留空，不得取正文提到的当事人或机关名；
- 件级再按件名**确定性兜底清空**，不依赖模型是否听话。

**决定七：成文日期用「文本位置档位 + 件内页位置」加权择优。**

成文日期是文书类档案的强纪律项：**正文中叙述的日期不得当作成文日期**。但文书正文常串起一串日期（合同签订日、事件发生日、原审判决日等），模型对这些正文日期的置信度往往还不低。实测 JZ07-2024-M2-0158 件 002（民事判决书，页 0002-0006）即取到了 0002 页正文里的 20231120，而真正的落款日期在 0005 页（20231218）。

但**不能简单地「取末页」**：成文日期也可能出现在**首页标题下方**（如通知书类文书的日期栏），只看页序会误判。故改为两级加权：

**① 文本位置档位（AIMP 页级重估，`_adjust_date_confidence`）**——用确定性判据覆盖模型自评置信度：

| 判据 | 档位 |
|---|---|
| 日期在 OCR 原文中有据，且**独立成行**（落款、标题下方的日期栏——同行前后除标点、空白外无文字） | 高 `0.95` |
| 有据，但**夹在正文句子中间**（「本院于2023年11月20日立案受理后…」） | 中 `0.5` |
| 原文中**找不到依据**（如页首归档章乱码编造） | 低 `0.15`（低于采纳门限 0.3，直接丢弃） |

原文用中文数字书写（「二〇一八年四月二十三日」）时，位置规则只认阿拉伯写法、无法判定是否独立成行，故**保持模型自评置信度**，不冒误杀风险。

**② 件内页位置加分（Java 件级，`DATE_EDGE_PAGE_BONUS = 0.1`）**——文书头尾（首页/末页）加分，中部页不加：成文日期总靠在文书的头或尾，中部的多是叙述性日期。分值只取 0.1 作微调，档位差（0.95 / 0.5 / 0.15）远比它大，页位置只在**同档位之间**起裁决作用。

两级相加取最高分者写入件级成文日期。页级提示词仍要求「成文日期取文书末尾落款处、与署名印章相邻的日期」，正文叙述的日期不得取——规则法与加权法形成双保险。

### 4.3 诉讼档案著录口径（依 mock 卷宗校准）

校准用的模拟卷宗（`g:\workshop\mock-data-gen`）为标准民事诉讼二审卷：59 页连续编页，顺序为
**卷宗封面 → 卷内目录（2 页）→ 件 01–26 → 卷底**，投放时拍平为 `0001.png`–`0060.png`，不含任何分件信息。

**① 页面性质判定（提示词新增 cover_page 类型）**

| 页面 | 判定 | 四要素取值 |
|---|---|---|
| 卷宗封面 | `cover_page` | 题名/责任者/文号/成文日期一律 null |
| 卷内目录 | `table_content_page` | 同上（不得把"卷内目录"当作某件题名） |
| 备考表、卷底 | `tail_page` | 同上 |
| 各件文书首页 | `header_page` | 按规则提取 |
| 文书续页 | `content_page` | 题名 null，其余视页面有无署名而定 |

**② 封面页定位：仅作要素来源，不单独成行**

封面页集中记载案号、案由、当事人、审级、收案与结案日期、原审法院及案号、审理结果、归档日期、保管期限等案卷级栏目，是这些要素的唯一可靠来源。处理方式：

- 提示词要求封面页**不著录为一件文书**，但必须提取案卷级要素；
- AIMP 侧封面页（第 1 页）的提取结果经 `previous_extractions` → `context_section` 流入其后各页的提示词上下文，供各件复用（为此 `_ELEMENT_DISPLAY_NAMES` 补齐了 `anyou/dangshiren/shenji/jiean_fangshi/baoguan_qixian/miji/kaifang_zhuangtai` 的中文名，否则上下文中会以裸 key 出现）；
- OpenRefine 侧按题名分件后，**题名为空的件（封面+卷内目录）不生成行**，其提取到的案卷级要素回填到其余各件的空值单元格；仅当整卷都无题名（提取全部失败）时保留该行，避免整卷一行都不出。

**③ 题名口径**

题名与卷内目录的「文书题名」一致，写法为**纯文种名**或**当事人+案由+文种**，多为短名：

    上诉案件移送函｜民事判决书（一审）｜民事上诉状｜民事答辩状｜二审受理案件通知书｜
    二审应诉通知书｜举证通知书｜合议庭组成人员通知书｜授权委托书（上诉人）｜
    授权委托书（被上诉人）｜律师事务所公函及律师执业证复印件｜当事人身份证明材料｜
    上诉案件受理费缴费凭证｜二审新证据及证据清单｜送达地址确认书｜
    送达回证（受理、应诉、举证、合议庭通知）｜开庭传票及送达回证｜询问笔录｜庭审笔录｜
    证据核对（质证）记录｜民事判决书（二审）｜宣判笔录｜送达回证及EMS邮寄底单｜
    结案登记表｜退卷函｜备考表

要点：**括号内容（一审/二审/上诉人/质证等）是题名的必要组成部分**，用于区分同类多件，必须原样保留；不得自行扩写为"×××诉×××…一案…"的长句（仅当页面本身印有完整长标题时才按原文著录）。

**④ 文号口径**

| 情形 | 取值 |
|---|---|
| 页面同时有案号与红头版头发文机关字号（如 `张中法〔2024〕51号`） | **一律取案号** |
| 法院制作的文书（判决书、通知书、传票、移送函、退卷函等） | 案号，如 `（2024)冀07民终241号` |
| 当事人提交材料（诉状、答辩状、委托书、证据、身份证明、缴费凭证） | null（不编文号，不得用案号填充） |
| 送达回证、各类笔录 | null |

不得取全宗号、目录号、案卷号、档号、卷内序号、快递单号。

**⑤ 责任者口径**

- 法院制作文书 → 制作法院名称，可用规范简称（如 `张家口中院`），不附带审判庭，**不得以审判人员个人为责任者**；
- 当事人提交材料 → 提交人姓名（如 `袁连顺、袁凤莲`），多个用中文全角逗号隔开；
- 律师事务所公函 → 律所名称；
- 本页无署名即返回 null，不得从其他页借用。

**⑥ 密级与开放标识**

- 密级：印在**版心左上角或标题下方**呈独立字样（如 `内部`）；取值枚举补齐为 **公开/内部/秘密/机密/绝密**，非密但标注内部管理的填 `内部`；
- 开放标识：取值仍为 开放/控制/延期开放，但明确**页面无"信息公开选项""开放标识"等字样时返回 null**——诉讼档案正卷扫描件通常不标此项，此前提示词未声明会导致臆造。

### 4.4 输出结构与卷级题名（性能与著录双向校准）

**① 输出只含识别到的要素**

多要素模板 `archive_multi_extraction` 的 JSON 骨架由「逐要素列出」改为**单个格式示例**，并要求「无法确定的要素直接省略，禁止输出 null 占位」。原写法下模型每页都要把全部要素（含大量 `null`）生成一遍，而多要素场景是**按页调用 LLM**、逐 token 解码，输出量直接决定耗时：

| 项 | 改前 | 改后 |
|---|---|---|
| 每页输出 | 全部要素 + null 占位 + `document_status` | 仅识别到的要素（典型 2–4 项） |
| 模板正文 | 约 1.1k 字（含骨架与页类型枚举） | 808 字 |
| 诉讼档案规则 | 1767 字 | 1132 字 |

**② 移除 `document_status`**

该字段（`content_complete`/`page_type`/`reasoning`）每页生成但**两端均无消费方**：AIMP 侧 `aggregate_previous_extractions` 只读 `elements`，OpenRefine 侧 `AimpLlmClient.parseTaskResult` 只读 `results` 与 `page_extractions`。已整体删除；页性质判断仍由规则正文的「【页面性质】」段落约束模型。

安全性：`_parse_multi_element_result` 对缺失要素本就会补默认空值，Java 侧只遍历返回值，故省略 null 不影响下游。

**③ 卷级题名**

原实现为「关于 + 各件事由 + 的 + 汇总文种」，但诉讼文书题名（`上诉案件移送函`、`民事判决书（一审）`）不匹配 `关于…的…` 结构，导致事由退化为整条题名、文种为空，卷级题名会变成 26 个件名的罗列。

改为**优先按诉讼档案著录惯例构成**，要素不足时才退回通用写法：

```text
立卷法院 + 关于 + 当事人 + 案由 + 一案 + 的审级 + 诉讼档案
例：河北省张家口市中级人民法院关于袁连顺、袁凤莲与袁凤仙、袁凤鸣继承纠纷一案的二审诉讼档案
```

- 立卷法院取**卷内制作文书件数最多**的法院（避免取到原审法院），并兼容"××中院""××高院"简称；
- 当事人、案由、审级取自扩展要素（封面页经回填流入各行）；
- 当「当事人或案由缺失」或「无法识别出法院」时，回退原通用写法。
