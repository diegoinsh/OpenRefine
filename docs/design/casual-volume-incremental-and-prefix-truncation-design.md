# 随案卷增量扫描与前序截断适配（预研记录）

- 状态：**已评估、未改造**，作为后续独立开发阶段的输入
- 记录时间：2026-10-27
- 触发：客户反馈随案卷不只「后向截断」（案子没结，卷尾材料还没产生），
  前向也会截断——前面阶段已整理著录完，随案子推进又有中间段材料需要扫描著录。
- 关联：`docs/extraction-feedback-loop-design.md`（RCP 侧闭环）、
  mock 侧 `security` 与 `benchmark/README.md`（GT / manifest）

## 一、业务场景

同一案卷（同一档号）分多批进机：

1. 第 1 批：收案至庭前材料，扫描、著录、人工核对完成；
2. 第 2 批：开庭至质证材料，新扫描若干页**追加**进同一卷；
3. 第 3 批：判决/送达材料，继续追加；
4. 也可能出现**中间插入**（后补的笔录排到已有页之间）与**卷首残缺**（第 1 页是某文书的中间页）。

关键诉求：每批只需抽新增页，**不能重抽全卷，更不能冲掉前一批已人工定稿的结果**。

## 三、结论

1. **追加页 → 整卷重抽**：能跑通，页码也正确（追加页编号接续即可）。
2. **同卷增量且保留历史行**：**当前不支持**。`resume=true` 会把该卷整卷跳过（新页丢失）；
   `resume=false` 清空全项目行（人工定稿丢失）。缺「按页 diff、只补新增页」的路径。
3. **同一档号分两批落两个目录**：会被识别成两卷、产生重复案卷号，不能自动合并。
4. **卷首残缺页**：第 1 页恒起一件；若该页无题名，卷级 LLM 分件可能并入后一件，
   字符串回退路径会产出一个**空题名幽灵件**（其责任者/成文日期大概率错）。
5. **中间插入页**：页码来自文件名，插入必须整卷重命名；且插入会改变邻页 `pageContext`，
   触发邻页缓存失效（可接受，但要知道成本）。
6. **反馈样本与 GT**：样本是「当前单元格 vs pageMap 候选」的快照，绑定 案卷号+件号+页区间；
   卷被重抽后旧样本页区间失效。mock 侧 manifest 目前只记后向截断（件清单 1..anchor），
   表达不了「起始件≠1、页码不从 001 起」的前向截断。

## 四、改造项（按优先级）

### P0 卷级增量（最小可用）

- 新增「增量模式」：按目录扫描出当前文件清单，与项目里已落库的该卷页清单做 diff；
  只抽新增页，其余件行与人工修改保留。
- 需要「卷版本」概念（每次增量入库记一个版本号 + 批次 id），供回溯与失效。
- 落点：`BatchExtractionManager` 的卷循环、`pruneUnitRows`、`BatchExtractionCommand` 的重跑分支；
  页清单持久化可挂在项目 metadata。

验收：同卷分 2 批入库（先 12 页后 +8 页），第 2 批只调 8 页 AIMP；第 1 批人工改过的格子值不变；
卷内起止页号连续、无重复件。

### P1 前序截断的卷首与要素策略

- 卷首页属「文书中间页」（无题名、无落款）时，明确策略：
  并入紧随其后的同文种件并标「前段缺失」，或单独成件但标灰不计数。
- 卷级要素在无封面/无裁判文书时的缺项语义与 `missingFields` 对齐（当前已支持，需补验证）。

验收：把一卷裁掉前 3 件后入库，产出的件数/题名与「应从第 4 件开始」一致，无幽灵件。

### P2 反馈样本与 GT 的版本化

- RCP 侧：样本记录卷版本/批次；卷重抽后旧版本样本自动失效（或按卷排除）。
- mock 侧：manifest 增 `start_piece` / `page_offset`（前向截断）与 `scan_batch`；
  `export_gt` 按「卷 + 批次」导出，同一档号可有多个 GT 版本。

### P3 中间插入页

- 插入会改变文件名编号：约定「插入后整卷重命名」，抽取侧按新文件名重新对齐；
  或支持按内容哈希去重、按锚点定位插入位置。
- 缓存失效策略：只让受影响的邻页与新增页失效。

## 五、评测与数据侧联动

- 新数据形态：mock 需能出「前向+后向都截断」的卷，并给出对应 GT；
  现有 `fyss_v1_stage` 是「只截尾」的形态，不能直接用于本场景验收。
- 评测口径不变（PDA / FDP / 边界@0 F1 / 件级 exact / 当事人 F1），
  但需要新增「批次」维度：同一档号多批次时逐批评测，不跨批合并。
- 训练样本：建议在 P2 完成后才把本场景样本纳入训练，避免页区间失效的样本污染。

## 六、边界（本次不做）

- 不引入 OCR/重排版；不对「跨卷合并」做通用能力（仍按一卷一目录）。
- 不改既有卷的渲染与截断基线（mock 侧 `CASUAL_PENDING_KEYS` 保持不动）。
- 手工删除页的裁剪版 GT（`fyss_v1_court15`）不作为本场景的真值来源，已由 `fyss_v1_stage` 取代。
