# 法院诉讼卷宗目录四级分层叠加方案

> 版本：v1.0　|　日期：2026-10-30　|　状态：方案（待评审）
> 适用工程：`OpenRefine`（FilesExtension 批量题名著录）+ `ruyi-aimp`（卷级分件与要素提取）+ `mock-data-gen`（离线预训练语料与回归真值）

---

## 1. 背景与要解决的问题

现状：法院诉讼卷宗的**第三级（件级题名）** 已实现——逐页 OCR → 页级题名 → 卷级分件 → 程序围栏（条项归并、附件并回、身份证明切件、题名规范化），产出卷内每一件的题名、责任者、文号、成文日期、页号。

甲方（法院/档案馆）手里的著录体系实际是**四级**：

| 级别 | 含义 | 本方案中的角色 |
|---|---|---|
| 一级目录 | 正卷 / 副卷 | 由本方案叠加 |
| 二级目录 | 卷宗封面、诉讼材料收取清单、案件移送函等表明案件来源的材料、答辩状及相关材料、交纳诉讼费用相关材料、反诉状及相关材料… | 由本方案叠加 |
| 三级目录 | 材料类别（现有件级题名） | 已实现，作为映射输入 |
| 四级目录 | 客户定制结果（按接口字段组合映射） | 已由接口完成，本方案只留对接位 |

甲方要求：**不能把他们的生产级四级目录直接固化进我们的产品**。因此本方案的核心命题是：

> 在产品里内置一套**通用底座**（法定/行业规范，各地可用），
> 生产环境再把**客户自己的目录**作为一"层"导入，
> 运行时用识别出的三级题名去匹配，落到客户口径的抽屉里。

一句话：**底座内置、口径可插、结果可审计、未匹配可回流**。

---

## 2. 为什么不能把客户目录固化进产品（三条硬理由）

1. **产权与合规**：客户的四级目录属甲方资产与内部制度文件，固化进我方交付物等于把客户资产分发到其他客户。
2. **通用性风险**：各地法院的二级分组与三级命名并不统一——有的按《立卷归档办法》条项名照录，有的自造名（"一审判决书""执行通知书"），有的粒度不同（3 份材料合著录 1 条）。固化任一家的口径，在另一家就会系统性错配。
3. **可维护性**：客户目录会随内部制度、法规修订而变化。固化意味着每次客户改目录我方都要重新发版，交付成本不可控。

因此架构上必须做到"**产品里没有客户目录原文**"——客户目录只在运行时的 `L1 客户口径层` 存在，随导入/撤销而生效或失效。

---

## 3. 设计原则

| 原则 | 说明 |
|---|---|
| 底座与口径分离 | L0（内置法定底座）与 L1（客户导入口径）物理分离，互不污染 |
| 确定性优先 | 一、二级判定为**纯程序映射**（词典/正则/优先级），不新增 LLM 调用，不增加单页耗时 |
| 可审计 | 每条结果带 `catalog_source`（internal / customer / unmatched）与置信度，错判可定位到规则条目 |
| 可回流 | 未匹配项进池，人工/半自动确认后补进 L1，形成收敛闭环 |
| 向后兼容 | 新增字段为**附加式**，不升 `api_version`；旧版 OR 忽略未知字段不报错 |
| 单点可关 | 复用现有 `archive_sub_category` 门控口径，仅法院诉讼档案生效；未开启的档案门类行为逐字段不变 |

## 4. 通用底座 L0：来源与构建

### 4.1 法源

| 依据 | 用途 |
|---|---|
| 《人民法院诉讼文书立卷归档办法》（1991-12-24）**第十条** | 排列总则（形成时间自然顺序，兼顾有机联系） |
| 同办法 **第十四条** | 民事一审正卷材料排列顺序（(3)~(21)，外加不编号的 (22)~(24)） |
| 同办法 **第十五条** | 民事二审正卷材料排列顺序 |
| 同办法 **第二十一条** | 副卷排列顺序（阅卷笔录、审查报告、内部交换意见、请示批复、合议庭评议笔录、审判庭研究记录、审委会讨论记录等） |
| 同办法 **第二十三条** | 卷宗封面、卷内目录、备考表、证物袋、卷底**不编号、不入目录** |
| 同办法 **第二十四条** | 目录逐件填写；一份诉讼文书材料编一个顺序号（**条项即顺序号**） |
| 《人民法院诉讼档案管理办法》（法〔2013〕283号）附件 1 | 案卷级与卷内文件级目录数据项；二级**分组**的权威措辞（"起诉状、上诉状、抗诉书、案件移送函等表明案件来源的材料"） |
| 各地电子卷宗/电子归档办法（山东、广州等） | 佐证"系统自动区分正副卷"是电子卷宗通行做法；作为二级分组措辞的参考语料，不进入产品硬编码 |

> 结论：**一、二级不是客户独有知识，而是法定/行业通行规范**。这正是"底座可以内置、且各地通用"的合法性来源。

### 4.2 语料采集（沿用 mock-data-gen 的抓网管线）

`mock-data-gen` 已有成熟的公开素材采集与规范整理能力，可直接扩展为 L0 语料来源：

- 既有：`templates/fetch_images.py`（检索词 → 样张）、`docs/ZY-专业档案/FYSS-人民法院诉讼档案/` 下的条文分册（`04-民事-一审正卷材料排列顺序.md`、`05-民事-二审正卷材料排列顺序.md`）。
- 扩展：按"法院名 + 卷内目录 / 归档办法 / 电子卷宗"检索公开样例目录，采集**条项名的变体写法**（同一材料在不同法院的称谓差异），汇入别名表。
- 产出不进入产品包，进入 `mock-data-gen` 的语料库并版本化登记。

### 4.3 L0 的四张表

| 表 | 内容 | 键 |
|---|---|---|
| T1 条项表 | 条项号 → 条项名 → 适用审级（一审/二审/刑事等） | `item_no + level` |
| T2 分组表 | 条项号 → 二级目录分组名 | `item_no` |
| T3 正副卷白名单 | 副卷材料的题名/正文关键词集合（封闭集） | 关键词 |
| T4 别名表 | 条项名的同义/简写/俗称变体（规范化用） | 变体 → 标准名 |

T2 分组表建议的分组口径（贴合 2013 办法附件 1 表述，可评审调整）：

1. 卷宗封面与卷内目录（不编号）
2. 表明案件来源的材料（起诉状、上诉状、抗诉书、案件移送函/移送书、原审裁判文书）
3. 交纳诉讼费用相关材料（受理费缴费凭证、非税收入一般缴款书）
4. 答辩状及相关材料（含反诉状及相关材料）
5. 当事人身份与委托材料（身份证明、主体资格、授权委托书、律所公函及执业证）
6. 举证与调查材料（原/被告举证材料、询问调查取证材料）
7. 审理过程材料（传票/开庭通知、庭审笔录、询问笔录、质证记录、调解笔录及调解材料）
8. 裁判文书（判决书、裁定书、调解书、司法建议书）
9. 送达与结案材料（送达回证及 EMS、宣判笔录、结案登记表）
10. 退卷与执行材料（退卷函稿及回执、上诉案件移送函存根、执行手续材料、证物处理手续）
11. 备考表/证物袋/卷底（不编号）
12. 副卷内部材料（阅卷笔录、审查报告、合议庭评议笔录、审理报告、裁判文书拟稿及签发稿、审委会讨论记录）

> 分组数不等于抽屉数——允许"一个分组下挂多个条项"，也允许**一个条项归两个分组**时按主材料定归属并在附注说明（见 §9 风险）。

## 5. 客户口径层 L1：导入与治理

### 5.1 导入内容

| 内容 | 必要性 | 说明 |
|---|---|---|
| 三级目录**全量词表** | 必须 | 客户所有可能出现的材料题名；这是 L1 的主体 |
| 二级归属（每个三级词对应的客户二级目录名） | 强烈建议 | 客户给了就等于零猜测；不给则由 L0 分组表推导 |
| 一级归属（该词属正卷还是副卷） | 可选 | 不给则由 L0 白名单判定 |
| 别名 / 简写 / 正则 | 可选 | 覆盖客户内部简称（"移送函"≈"上诉案件移送书"） |
| 优先级 | 可选 | 一词多义时的取舍（如"通知书"需结合上下文时降级） |

### 5.2 导入格式（建议）

```json
{
  "catalog_version": "CUST-2026.10",
  "customer": "某省高院",
  "level1": ["正卷", "副卷"],
  "entries": [
    {"level1": "正卷", "level2": "表明案件来源的材料", "level3": "民事起诉状",
     "aliases": ["起诉状", "起诉书"], "match_type": "exact"},
    {"level1": "副卷", "level2": "副卷内部材料", "level3": "合议庭评议笔录",
     "aliases": ["合议笔录"], "match_type": "keyword"}
  ]
}
```

### 5.3 导入治理

- **校验**：层级非法、二三级重复、同一三级词被指派到两个不同二级（冲突）、与 L0 条项明显矛盾（提示不阻断）。
- **版本化**：客户目录带版本号与生效时间；保存历史版本，支持新旧版本差异对比（新增/删除/改名各多少条）。
- **灰度**：先"影子模式"（只比对不生效），确认未匹配率与冲突数达标后再切换为生效。
- **撤销**：撤销后自动回落 L0，产品回到"无客户口径"状态，验证"未固化"承诺。

## 6. 运行时映射（L2）

### 6.1 流程

```
件题名（分件围栏输出）
  → ① 规范化：T4 别名表 + L1 别名 → 标准题名
  → ② 匹配 L1（精确 → 别名 → 关键词 → 正则，按优先级）
       命中 → 二级/一级取自 L1（客户口径）
  → ③ 未命中 → 匹配 L0（T1/T2/T3）
       命中 → 二级/一级取自 L0（catalog_source=internal）
  → ④ 仍未命中 → catalog_group = "待归类"，catalog_source = unmatched
```

### 6.2 一级（正副卷）判定

- **逐件判定（默认）**：命中 T3 副卷白名单（题名或抽样正文关键词）→ 副卷；否则正卷。
- **整卷判定（可选）**：客户按正/副分卷扫描时，由目录/文件夹或卷首材料直接定整卷，逐件不再判。
- 副卷白名单是**封闭集**（第二十一条列举项），故误判风险主要来自"正卷中出现了同名词"——用"题名优先、正文仅在被要求时参与"降低误判。

### 6.3 与既有围栏的衔接

现有分件流水线（`ruyi-aimp` `web_service.split_pieces`）在返回前依次执行：未题名首件清理 → 强条项名补漏 → 无题名件吸收 → 诉状附件并回 → 尾部移交 → 条项归并 → 判决书拆分 → 再归并 → 误报判决书尾吸收 → 身份证明切件 → 题名规范化 → 同名件尾吸收。

本方案**在这条流水线之后追加一步纯后处理**（不改变任何既有步骤与顺序），为每个 piece 附加一、二级字段。因此：

- 既有分件结果逐字段不变（除新增字段）；
- 一、二级判定可离线单测，不依赖模型；
- `archive_sub_category` 未以"诉讼档案"结尾时整步跳过，其他档案门类零影响。

## 7. 数据结构与接口契约

### 7.1 AIMP 响应（`/extract/split-pieces` → `SplitPiecesResponse`）

`pieces[]` 每项在既有 `start / end / title` 之外**追加**：

| 字段 | 类型 | 含义 |
|---|---|---|
| `volume_type` | string | `正卷` / `副卷` |
| `catalog_group` | string | 二级目录名（客户口径优先，L0 兜底，否则 `待归类`） |
| `catalog_title` | string | 规范化后的三级题名（对齐客户词表后的写法） |
| `catalog_source` | string | `customer` / `internal` / `unmatched` |
| `catalog_conf` | float | 置信度 0~1（精确=1.0，别名 0.9，关键词 0.8，正则 0.7，未匹配 0） |

### 7.2 兼容性

- 属于**附加式**字段：不升 `api_version`；调用方（OR）按"字段可能缺失"处理。
- OR 未升级时忽略未知字段，不报错。
- OR 侧卷内表新增两列"正副卷""二级目录"，只读展示、可随导出；不进入现有件号/页码逻辑。

### 7.3 客户目录的承载位置（三选一，见 §12 开放问题）

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. AIMP 本地配置文件 + 导入接口 | 与现有一致（配置驱动），离线可测 | 多客户多实例需分文件管理 |
| B. 平台（ruyi-capability-platform）下发 | 集中管理、多租户友好 | 需要平台侧新接口与权限 |
| C. OR 侧上传随项目走 | 贴近使用场景 | 目录成为项目数据，跨项目复用差 |

建议：**短期 A（先跑通），中期 B（多租户）**。

## 8. 离线预训练框架（不依赖客户的可行性验证）

目标：在客户目录尚未导入前，用 mock 语料把"底座 + 映射 + 指标"这套框架训练/验证到可交付状态。

> 说明：此处"训练"是**规则与词典的构建与回归**，不是模型训练；整条链路是确定性的。

### 8.1 步骤

1. **语料与真值**：`mock-data-gen` 渲染的卷宗自带标准卷内目录（含条项列），即真值来源——二审卷 `JZ07-2024-M2-0241`（正卷 26 件 + 副卷 6 件）、一审卷 `SZ05-2025-M1-4821`（25 件）、二审卷 `SZ05-2025-M2-0158`。
2. **跑真实链路**：渲染 → OR 批量提取 → AIMP 分件 → 得到件题名。
3. **执行映射**：L0 单独运行（不导入客户目录），产出 `volume_type` / `catalog_group`。
4. **逐件比对**：以 mock 真值目录的"条项列"为基准，比对一级、二级归属。
5. **出报告**：进入 `mock-data-gen/benchmark/runs/` 体系，可多轮 `compare`。

### 8.2 指标与门槛（L0 单独，即"客户尚未导入目录"的最坏情形）

| 指标 | 口径 | 门槛 |
|---|---|---|
| 一级（正副卷）准确率 | 件级比对 | ≥ 98% |
| 二级分组准确率 | 件级比对（分组名等价即可） | ≥ 95% |
| 未匹配率 | `catalog_source=unmatched` 占比 | ≤ 3% |
| 三级题名准确率 | 现有口径，不因本方案退化 | 不低于改造前基线 |

> 达标即证明"底座可用、架构成立"；此后客户导入 L1 只会更好，不会更差。

### 8.3 mock 的边界（必须写清）

mock 的三级题名是按法定条项名生成的（"标准口径"），因此：

- ✅ 能验证：映射表正确性、分件边界、判定算法、回流机制；
- ❌ 不能验证：客户自造名、粒度差异、地区差异——这些只能由真实客户词表与样卷覆盖。

## 9. 客户上线流程（生产）

**阶段 1 · 影子模式（只读比对，不生效）**

- 导入客户目录 → 对历史/新跑卷宗同时产出"我方口径"与"客户口径"两套结果 → 统计未匹配率、冲突数、二级归属差异。
- 产出《口径差异清单》交客户确认（常见：客户把两份材料合成一条、客户二级名与我方分组名不同但语义一致）。

**阶段 2 · 生效**

- 客户口径优先、L0 兜底；`catalog_source` 标记来源便于抽检。
- 约定验收：匹配正确率 ≥ 95%，未匹配率 ≤ 3%（首轮可放宽未匹配 ≤ 10%，收敛期收紧）。

**阶段 3 · 回流收敛**

- 未匹配池 → 人工确认（一次点击归入某抽屉）→ 自动补进 L1 → 版本递增。
- 稳定后未匹配率单调下降，运营成本趋零。

---

## 10. 准确率口径（避免含糊承诺）

拆为三个可量化指标，而非笼统"准确率"：

- **覆盖率** = 已归类件次 / 总件次
- **匹配正确率** = 归类正确的件次 / 已归类件次
- **未匹配率** = 落"待归类"的件次 / 总件次（**不计入错误，但必须可统计**）

合同/验收建议按"匹配正确率 + 未匹配率"双指标承诺，未匹配项走回流，避免把长尾词算成错误。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 客户著录粒度与我方不同（合著录/细拆） | 二级归属错配、一题跨两抽屉 | 样卷校准；冲突时按主材料定并附注；必要时允许 `catalog_group` 为"主分组（附：副分组）" |
| 客户目录改版 | 历史映射失效 | 版本化 + 差异对比 + 灰度切换 |
| 法规更新（办法修订） | L0 过期 | L0 独立版本化，随法规更新发布，不影响 L1 |
| 地区差异 | 单一 L0 不够贴 | 正是 L1 存在的理由；L0 只保证"大类正确" |
| LLM 题名本身错 | 映射连锁错 | 用 L1 词表反向注入 `canonicalize_court_piece_titles`，题名规范化与抽屉归属双收益 |
| 客户要求我方"预置他们的目录" | 回到固化风险 | 明确写入合同：客户目录仅以导入形式存在于运行时，产品不含其原文 |
| 多客户共用一套部署 | 口径串味 | L1 按客户/机构隔离，请求带 `catalog_version` 选择生效层 |

## 12. 实施路线

| 阶段 | 内容 | 依赖客户 | 产出 |
|---|---|---|---|
| **P0** 底座与离线框架 | 构建 T1~T4、映射算法、`volume_type`+`catalog_group` 字段、mock 三卷回归报告 | 否 | 指标达标（§8.2） |

| **P2** 生效与回流 | 客户口径生效、未匹配池、回流补词；OR 新增两列 | 是 | 生产准确率验收 |
| **P3** 四级对接预留 | 四级（客户定制字段组合）接口位，本方案不实现 | 是 | 接口留位 |

P0 可立即开工，且 P0 完成前不产生任何客户数据依赖——这也是本方案"先搭框架、后接口径"的核心节奏。

## 13. 开放问题（需评审确认）

1. **客户目录承载位置**：A（AIMP 配置文件）/ B（平台下发）/ C（OR 侧上传）——建议短期 A、中期 B。
2. **二级分组全集口径**：采用 §4.3 的 12 组，还是客户/行业另有既定分组（若客户已有二级名，直接以其为准，L0 仅作兜底）。
3. **不编号件（封面/目录/备考表/证物袋/卷底）**：此前决策"不写入条目行"。本方案二级分组含"卷宗封面"，需确认这些页**是否单列一行只标分类、不进件号序列**，或仍只在分组表中体现而不出条目。
4. **正副卷扫描组织方式**：同文件夹混排（逐件判定）还是分卷扫描（整卷判定）——影响 §6.2 采用哪种模式。
5. **一题多抽屉**：是否允许 `catalog_group` 输出主+附两个值。
6. **四级字段组合规则**：需确认四级所用的三级键与客户四级字段的对应表（用户表示已通过接口完成，需对齐键名）。
